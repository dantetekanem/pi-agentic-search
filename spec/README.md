# Repository architecture draft

Status: descriptive draft awaiting the maintainer's confirmation, not an approved architectural rule. Inspected source: `a5174ad60c6f162911dc17efb9f5d4d47551beee` (package 0.7.1). These documents describe that revision; they do not establish the state of an installed package or other branches.

`pi-agentic-search` is a local code-navigation package. It ranks ripgrep matches and gathers static Ruby/JavaScript/TypeScript context around a definition or Git diff. A standalone CLI and Pi tools share the implementations. It is not a hosted search service or a runtime call tracer.

- [Architecture and flows](architecture.md) explains boundaries, lifecycle, storage and presentation.
- [Decisions and open questions](decisions.md) separates recorded choices from inferred rationale.
- [Usage and development](../README.md), [runtime access](../docs/access.md) and [evaluation](../docs/evaluation.md) remain the detailed references. This draft does not replace them.

## Folder responsibilities

| Area | Responsibility and first place to look |
| --- | --- |
| [index.ts](../index.ts) | Pi extension entrypoint and selected library exports. |
| [bin/](../bin/agentic-search.mjs) | Node launcher for the compiled CLI; `dist/` is generated by the build, not a second implementation. |
| [src/cli.ts](../src/cli.ts), [src/extension.ts](../src/extension.ts), [src/sparsity-extension.ts](../src/sparsity-extension.ts) | CLI argument/output lifecycle and Pi registration, rendering and storage policy. |
| [src/search.ts](../src/search.ts) and adjacent modules | Search orchestration; retrieval/execution own rg processes and budgets, inventory owns request-local filesystem facts, ranking/evidence select results, format/coverage-summary explain them. |
| [src/resolvers/](../src/resolvers/) | Ranked-search relationships: supported Ruby mixins/constants and JS/TS imports, aliases and packages. The compiler host resolves modules using bounded filesystem facts. |
| [src/sparsity.ts](../src/sparsity.ts), [src/sparsity-scan.ts](../src/sparsity-scan.ts), [src/context.ts](../src/context.ts) | Definition/call collection, diff-to-pack orchestration and shared option normalization. `sparsity-shared.ts` contains context path/Git helpers; `metrics.ts` records context-run summaries. |
| [src/adapters/](../src/adapters/) | Parsed definition/call facts for context collection: Prism Ruby, TypeScript programs/checkers and the Ruby index/cache. These are distinct from ranked-search resolvers. |
| [test/](../test/) | Executable regressions, smoke scripts, synthetic benchmarks and frozen public-corpus/model-evaluation tooling. Tests are here, not in `spec/`. |
| [docs/](../docs/) | Access policy details, evaluation methodology and saved benchmark evidence. |
| [skills/](../skills/agentic-search/SKILL.md) | Portable instructions for agents using the tools or CLI. |
| [.github/workflows/](../.github/workflows/) | CI verification and release-triggered package staging. |
| [spec/](README.md) | This source-grounded architecture draft; no test configuration changes. |

## Inspection limits

The inspection followed entrypoints through search execution/related expansion, context setup, diff/head handling and artifact writing. It read parser/program/cache setup, the runtime access document, workflow definitions and selected Git messages. It did not exhaustively inspect every resolver branch, inference heuristic or test. Source paths and named symbols in the linked documents are navigation anchors, not executed proof.

No dependencies were installed, and no builds, tests, benchmarks, live models, browser checks or service probes ran for this documentation change. CI and publishing descriptions are workflow definitions, not fresh run results. The package manifest's `files` list does not include `spec/`; these drafts are repository documentation, not a promised npm artifact.
